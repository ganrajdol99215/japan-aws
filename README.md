# W2P Japan - Personal AWS Replica Lab

This package is a sanitized, deployable learning replica based on the uploaded W2P Japan CloudFormation templates. It is **not** the client environment and contains no client account IDs, resource IDs, domains, or SNS ARNs.

## Important architecture note
The original client had some resources already existing outside these CloudFormation stacks: the VPC/public subnet, Route 53, and ACM were not created by Siva's five templates. The lab therefore adds `00-foundation.yaml` only to create a personal VPC/public subnet and two SNS topics so the rest can be deployed from scratch. Route 53 and ACM remain outside the five-stack replica, matching the client's separation.

## Stack order
1. `00-foundation.yaml` - lab VPC, public subnet, IGW, public route table, SNS topics
2. `01-network.yaml` - private subnet, private route table, optional NAT/EIP/default route
3. `02-compute.yaml` - IAM, security group, EC2, CloudWatch Agent, alarms
4. `04-waf.yml` - deploy in **us-east-1** for CloudFront scope
5. `03-cloudfront.yaml` - CloudFront VPC Origin + distribution; optionally attach WAF ARN
6. `05-backup.yaml` - AWS Backup vault, plan, and EC2 selection

## Why WAF before CloudFront?
The WAF stack is independent and exports its ARN as an output. The CloudFront stack accepts the ARN as a normal parameter. Therefore you can create WAF first, copy its ARN, and then deploy/update CloudFront with that ARN.

## Personal-account substitutions
- VPC/subnet IDs: generated by `00-foundation.yaml`
- AMI: choose the current Amazon Linux 2023 AMI in your selected Region
- Key pair: create your own EC2 key pair
- CloudFront origin-facing prefix list: retrieve the AWS-managed prefix list in your Region
- SNS: created by the foundation stack instead of using client SNS ARNs
- Project/Environment/Owner: `W2P-Japan-Lab` / `dev` / `Ganraj`

## First deployment
Use the AWS Console first so every parameter and resource can be observed. After the first successful deployment, repeat with AWS CLI to learn the operational workflow.

For production-style updates, create a CloudFormation change set and review additions/replacements/deletions before execution.
